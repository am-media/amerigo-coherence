# Prototype
**When:** Technical feasibility or user utility is uncertain.
**Decide:** Name the riskiest assumption, the smallest experiment, and the evidence needed to resolve it.
**Build:** One usable vertical slice; prefer an existing tool or single process. Explicitly exclude scalability or generic infrastructure unless being tested.
**Verify:** Demonstrate the actual outcome; mocked tests alone are insufficient for integration claims.
**Stop:** Adopt if fit for real use; otherwise record FIX / PIVOT / ABANDON with evidence. A prototype may be the final product.
**Escalate:** After two unsuccessful attempts at the same acceptance goal, reassess before further implementation.
